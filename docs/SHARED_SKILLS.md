# Общие навыки

Канонический редактируемый источник — `skills/<имя>/SKILL.md` и его ресурсы. Общая логика не содержит обязательных локальных путей или конкретных MCP. В `adapters/<платформа>.md` — возможности и ограничения среды. Сборщик вставляет адаптер в маркер `<!-- PLATFORM_ADAPTER -->`; результаты в `.skill-build/` не редактировать и не коммитить.

```text
skills/concepts/ → bin/skills.py + adapters/
  → .skill-build/codex/concepts/       ← ~/.agents/skills/concepts
  → .skill-build/claude-code/concepts/ ← ~/.claude/skills/concepts
  → .skill-build/claude-chat/concepts.zip
  → .skill-build/chatgpt/concepts.zip
```

Основной источник редактируется в `skills/`; локальные `SKILL.md` связаны с ним напрямую. Для пересборки облачных пакетов после изменения исходников: `python3 ~/.agent-rules/bin/skills.py build`.
Первое локальное подключение: `python3 ~/.agent-rules/bin/skills.py install`.
Ссылки обновляются после сборки, новые навыки подключаются повторным install. Существующие каталоги и ссылки с другим назначением вызывают ошибку до установки. Handoff и каталоги synced не затрагиваются. Новую сессию агента открыть для обновления списка навыков.

Для Claude Chat загрузить `.skill-build/claude-chat/concepts.zip` через управление Skills, обновив уже существующий Concepts (не создавая дубль). Для ChatGPT, если доступно: Plugins → Skills → Create → Upload from your computer, выбрать `.skill-build/chatgpt/concepts.zip`. При обновлении использовать управление существующим навыком. Если Skills недоступны, приложить сгенерированный `chatgpt/concepts/SKILL.md` к чату и явно попросить применить его; это действует в контексте чата, а не как глобальная установка.

Облачные загрузки — версии на момент сборки, не живая ссылка на Mac. После каждой правки нужна повторная загрузка. Скрипт не входит в облачные аккаунты, не устанавливает Skills через недокументированные API и не меняет уже установленный Concepts. Возможная синхронизация claude.ai → Claude Code не даёт общей синхронизации четырёх платформ: при одноимённых навыках нужно проверить источник в списке навыков Claude Code. Автоматически удалять synced-версии нельзя.

Проверка формата и ссылок не доказывает автоматический выбор навыка моделью. Приёмка в новой сессии каждой платформы: попросить применить concepts к аудиту конкретного экрана без правок; убедиться, что навык выбран, аудит не меняет файлы, отсутствие подключений указано. Второй сценарий: правка существующего экрана, сохранение носителя, без незапрошенной мобильной версии. Облачная установка и эти поведенческие проверки требуют доступной учётной записи.

## Проверенные источники, 25.11.2026

- https://code.claude.com/docs/en/skills — локальные навыки, synced и приоритеты.
- https://developers.openai.com/codex/skills — SKILL.md и ссылки на каталоги.
- https://support.claude.com/en/articles/12512198-how-to-create-custom-skills — ZIP с каталогом навыка.
- https://help.openai.com/en/articles/20001066-skills-in-chatgpt — загрузка; доступность зависит от аккаунта и workspace, документация перечисляет Business, Enterprise, Healthcare, Edu. Формат ZIP должен пройти реальную загрузку: локальная сборка не подтверждает принятие сервером.

## Обновление из любой среды: общий MCP

Требование «поменять в любой из четырёх сред — подхватить везде» реализуется через общий источник с записью, а не обмен ZIP. Подготовлен `bin/skills_mcp.py`: `list_skills`, `read_skill`, `update_skill`. Перед применением клиент читает текущий навык; перед записью передаёт SHA-256 прочитанной версии. Конфликт возвращает ошибку, а не затирает чужую правку. Запись пересобирает адаптеры и облачные пакеты. Локальные SKILL.md — ссылки непосредственно на канонический файл: правки из Claude Code и Codex попадают в один файл; `platform.md` рядом задаёт среду. Общие ресурсы тоже связаны ссылками. Непосредственные одновременные записи файлов не защищены CAS: для параллельного редактирования используйте update_skill.

Локальный MCP запускается через `python3 ~/.agent-rules/bin/skills_mcp.py` по stdio. Вторая возможность — `--http PORT`, только 127.0.0.1, POST /mcp, Bearer из SHARED_SKILLS_TOKEN (не менее 32 символов, env/keychain). Сервер не запускается автоматически и порт наружу не открывается. Он не выполняет содержимое навыков как код и не принимает произвольные пути. Автокоммит/пуш через MCP не выполняется: локальный git остаётся механизмом версии и ревью.

**Облачное подключение ещё не реализовано.** Чтобы Claude Chat и ChatGPT действительно читали/писали общий источник, нужны постоянно доступный HTTPS-хост, аутентификация, поддерживаемая обоими клиентами (при необходимости OAuth-шлюз), регистрация MCP-коннектора и начальная инструкция читать актуальный навык через read_skill. Локальный HTTP с Bearer сам по себе не доказывает совместимость с интерфейсом подключения этих продуктов. На Mac, который выключен или недоступен из сети, облачный доступ работать не будет. Нативные загруженные Skills останутся отдельными копиями: общий MCP не меняет их редакторы автоматически. Для правок в обычном чате надо обращаться именно к общему MCP, а не редактировать независимую копию в библиотеке платформы.

Сервис — подготовленная и локально проверяемая основа, не завершённая четырёхсторонняя синхронизация. Проверка реального HTTPS/OAuth и четырёх клиентов остаётся открытой. Не выдавать сборку пакетов за выполнение этого требования.

## Приёмка обычного запроса

В новой сессии каждой среды отправьте «Сделай два концепта экрана подписки для приложения заметок» без названия навыка, команды или вложения. По журналу вызовов проверьте, что выбран Concepts и прочитана текущая версия. Повторите после правки из каждой среды. Нативная активация и синхронизация проверяются отдельно. MCP-прототип выше не подключён и не заменяет нативную активацию. Установленные Skills Claude Chat сохранены, в ChatGPT установка не проверена.
