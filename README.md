# agent-rules

Глобальные правила работы с Никитой для Claude Code и Codex и механизм, который сам пополняет их наблюдениями из сессий в Orca.

> **Агенту, который открыл этот репозиторий.** `CLAUDE.md` здесь не инструкция к репозиторию, а сам глобальный файл правил. Его читают все сессии обоих агентов во всех проектах. Инструкция к репозиторию — этот README. Правишь `CLAUDE.md` вручную — сохраняй структуру разделов: скрипт вливает правила по точным заголовкам.

## Состав

| Путь | Что это |
|---|---|
| `CLAUDE.md` | Глобальные правила. Разделы `##`/`###`/`####`. В конце может быть раздел `## На решение` |
| `bin/rules_sync.py` | Скрипт пополнения. Python 3.9 (системный `/usr/bin/python3`), без зависимостей |
| `bin/prompt.md` | Системный промпт для модели-извлекателя: что считать правилом и формат ответа (JSON) |
| `.state/` | В git не входит. `state.json` — какие сессии разобраны и что в очереди; `log.txt` — журнал; `lock`; `launchd.err` |

## Как файл подключён к агентам

Цепочка симлинков, сам файл один:

```
~/.claude/CLAUDE.md  → ~/.agent-rules/CLAUDE.md              (Claude Code)
~/.codex/AGENTS.md   → ~/.claude/CLAUDE.md                    (Codex)
~/Library/Application Support/Orca/codex-accounts/<id>/home/AGENTS.md → ~/.codex/AGENTS.md   (Codex внутри Orca)
```

Orca запускает Codex со своим `CODEX_HOME`: `~/Library/Application Support/Orca/codex-accounts/<id>/home`. Там отдельные `hooks.json`, `config.toml` и `sessions/`.

## Как работает пополнение

```
закрытие сессии ─► хук SessionEnd ─► rules_sync.py kick ─► (фон, через ~2 мин) run
launchd раз в час ──────────────────────────────────────────────────────────► run
```

`run`:
1. **collect.** Обходит переписки (см. «Источники») и берёт только файлы, которые изменились и не менялись последние `QUIET_SEC`, то есть сессия закрыта. Отсчёт по каждой сессии идёт по числу реплик пользователя (`done`). Поэтому продолженная позже сессия разбирается только в новой части.
2. **Локальный фильтр, без модели.** Из новых реплик пользователя остаются только те, что совпали с регуляркой `SIGNAL`: поправки, «опять», «всегда», «не надо», «запомни» и т. п. Перед этим вырезаются `<system-reminder>`, `<pasted_content>` (→ `[вставка]`), прочие XML-блоки, код, ссылки, почты. Сводки при сжатии контекста, служебные команды и вывод инструментов отбрасываются. К каждой сигнальной реплике добавляется контекст: предыдущая реплика пользователя и хвост ответа агента. Сессия без сигналов помечается разобранной и в модель не идёт.
3. **Очередь.** Выдержки копятся в `state.pending`. Модель вызывается, когда выдержек `≥ MIN_SIGNALS` или самая старая ждёт дольше `MAX_WAIT_H`. Лимит — `DAILY_CAP` вызовов в сутки. В один вызов идёт пачка до `BATCH_CHARS` символов, остаток ждёт следующего.
4. **Модель.** Основной путь — `claude -p --model sonnet` в пустой временной папке, без инструментов, MCP, плагинов, настроек и сохранения сессии (`--setting-sources "" --tools "" --strict-mcp-config --disable-slash-commands --no-session-persistence --system-prompt …`). Накладные около 600 токенов. Если вызов не удался (лимиты), идёт запасной путь — `codex exec --ephemeral --ignore-user-config …` с подменой инструкций. Он дороже: около 20 000 токенов накладных. Модель получает текущий `CLAUDE.md` и выдержки и возвращает `{"ops":[…]}`.
5. **Применение (`apply_ops`).**
   - `add` вставляется последней строкой раздела с точно таким заголовком.
   - `conflict` (и `add` в несуществующий раздел) уходит в `## На решение` в формате «**Было:** … → **Предлагается:** … _(источник, дата; «цитата»)_». Существующие правила скрипт **никогда не меняет и не удаляет**.
   - Отсев: дубли (`is_dup`: точное совпадение или подстрока после нормализации, либо ≥ 80 % общих слов), а также строки с секретами и персональными данными (`SECRET`: токены, длинные hex/base64, ссылки, figma, телефоны, пароли; `EMAIL`: любые почты, кроме `OWN_EMAIL`). Не больше 5 операций за вызов.
6. **Коммит и пуш.** Автор — `Никита Егоров <egorov.d.nikita@mail.ru>`. Заголовок вида `Правила: +N, на решение M`, в теле список правил и источник (агенты и число сессий). Затем `git push`. Если пуш не прошёл, это пишется в журнал.

Если модель вернула невалидный ответ, пачка остаётся в очереди. Если ответ пустой (`{"ops":[]}`, это обычный случай), пачка снимается без коммита.

## Источники переписок

| Агент | Где | Что берётся |
|---|---|---|
| Claude Code | `~/.claude/projects/*/*.jsonl` | Только `entrypoint == "cli"` (Orca запускает CLI). Десктоп Claude и SDK-запуски, включая собственные `claude -p`, отсекаются |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` и `…/Orca/codex-accounts/*/home/sessions/**` | Только `session_meta.originator ∈ {codex-tui, orca_desktop, codex_cli_rs}`. Codex Desktop, guardian-сабагенты и `codex exec` отсекаются. Реплики берутся из `event_msg` → `item_completed` (`UserMessage`/`AgentMessage`) и из старого формата `user_message`/`agent_message` |

Чаты в приложениях ChatGPT и Claude сюда сознательно не входят: там своя память.

## Что установлено вне репозитория

| Что | Где |
|---|---|
| Хук Claude Code | `~/.claude/settings.json` → `hooks.SessionEnd`, команда `/usr/bin/python3 -I "$HOME/.agent-rules/bin/rules_sync.py" kick 2>/dev/null \|\| true` |
| Хук Codex | `~/.codex/hooks.json` и `~/Library/Application Support/Orca/codex-accounts/<id>/home/hooks.json` → `SessionEnd`, та же команда. Codex требует один раз одобрить новый хук (trust); после изменения команды хука одобрять придётся заново |
| launchd | `~/Library/LaunchAgents/local.agent-rules.sync.plist`: `run` раз в час и при входе в систему |
| Резервные копии хуков | рядом с файлами хуков, суффикс `.rules-sync-<дата>.bak` |

Рядом стоят хуки Orca и Agent Pulse. Их не трогать. Orca может перегенерировать свой `hooks.json` при обновлении: если запись `rules_sync.py` пропала, верни её. Ежечасный `run` работает и без хуков.

## Команды

```sh
python3 ~/.agent-rules/bin/rules_sync.py status       # очередь без вызова модели
python3 ~/.agent-rules/bin/rules_sync.py run          # разобрать сейчас (с учётом порогов)
python3 ~/.agent-rules/bin/rules_sync.py run --force  # вызвать модель, даже если порог не набран
python3 ~/.agent-rules/bin/rules_sync.py init         # точка отсчёта: всё существующее считать разобранным
tail ~/.agent-rules/.state/log.txt                    # журнал: kick (проект, причина), токены вызова, коммиты, отсевы
git -C ~/.agent-rules log -p                          # что и когда добавилось
launchctl kickstart gui/$(id -u)/local.agent-rules.sync   # запустить launchd-задачу вручную
```

Отменить автоизменение: `git revert <коммит>`, затем `git push`.

## Настройки (константы в начале `rules_sync.py`)

`QUIET_SEC=120` · `MIN_SIGNALS=3` · `MAX_WAIT_H=24` · `DAILY_CAP=4` · `MSG_CHARS=300` · `CTX_CHARS=200` · `BATCH_CHARS=12000` · `CLAUDE_MODEL="sonnet"` · `CODEX_ORIGINATORS` · регулярки `SIGNAL`, `SECRET`.

Ориентир по расходу (замер 19.11.2026): за две недели истории 63 сессии, сигналы нашлись в 16, всего 19 выдержек, около 7 400 символов. Один вызов — около 9 000 токенов входа: примерно 4 500 на файл правил, остальное на выдержки и промпт.

## Защита от зацикливания

- `kick` ничего не делает, если задана переменная окружения `RULES_SYNC_CHILD`. Её выставляют фоновый процесс, launchd и дочерние вызовы `claude`/`codex`.
- `claude -p` запускается с `--setting-sources ""` (хуки не грузятся) и `--no-session-persistence`. Его переписки не сохраняются, а если бы сохранились, их отсёк бы фильтр по `entrypoint`.
- `codex exec --ephemeral` не пишет сессию, `originator=codex_exec` в фильтр не входит.
- `flock` на `.state/lock`: одновременно работает только один `run`.

## Как дорабатывать

- **Проверяй на копии**, а не на живом файле. Скопируй репозиторий во временную папку, подмени в импортированном модуле `ROOT`, `RULES`, `STATE_DIR`, `STATE`, `LOG` и вызывай `apply_ops([...], "тест")` или `run(force=True)`.
- Меняешь формат чтения переписок — сначала посмотри реальные файлы. Форматы Codex менялись между версиями (`event_msg.user_message` → `item_completed.UserMessage`).
- Меняешь `SIGNAL` — прогони `excerpts()` по сессиям за две недели и посмотри, что проходит. Цель: мало шума, без разовых просьб.
- Меняешь `prompt.md` — помни, что модель видит весь `CLAUDE.md`. Каждый лишний символ файла правил стоит токенов в каждом вызове.
- После правок скрипта: `python3 -I -c "import ast;ast.parse(open('bin/rules_sync.py').read())"`, затем коммит и пуш. Хуки и launchd вызывают скрипт по пути, переустанавливать ничего не нужно.
